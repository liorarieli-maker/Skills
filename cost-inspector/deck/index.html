Claude Code Cost Audit

01 / The problem

The budget runs out before the month does.

AI is expensive, so companies cap it. But a cap doesn't make anyone cheaper — whether you set it or live under it. Hit it on the 22nd and you're either asking for more, or working without AI until the 1st.

Monthly budget$500
Gone by the 22nd$500
Option Aask for more
Option Bno AI till the 1st
Neither is a plan↓

And "be more efficient" isn't advice anyone can act on. Knowing what actually costs money means understanding half a dozen things about how Claude Code works — which most people won't learn, and shouldn't have to. You can see the number. Nobody explains it, and nobody coaches you.

02 / Two skills, split on purpose

One gives facts. One gives opinions.

Two installs, because you'd use them at very different rates. One is cheap enough to run any time. The other costs real money and reads your actual conversations — so you only install it if you want that.

cost-inspector

Facts · pennies a run · read-only

Looks at your settings and your usage counters — how much you used, which model, which tools. Just arithmetic.

It never reads what was said. Not behind a flag, not behind a prompt.

Nothing leaves your machine. The few pennies are just the report being read back to you.

cost-coach

Opinions · a few dollars a run · opt-in

Reads a handful of your real conversations and points out the habits costing you money — quoting your own words as proof.

Asks permission and shows the price before it reads anything.

03 / What it checks

16 checks, four kinds of waste.

A · ALWAYS ON
Paid on every message
Skills and plugins you never use, instruction files that got too long, connected services you never call.
B · PRICE
What each message costs
Which model you start on, how hard Claude thinks before answering, and what its helpers use.
C · CACHE
Paying twice for the same text
Claude re-uses your conversation at a tenth of the price. When that breaks you pay twice — and a session left open all day carries everything said in it.
D · HABITS
How you work
Screenshots, which stay in the conversation and are paid for on every message after. The same file read twice.

Skills I never ran were adding 1,595 tokens to every message I sent — their descriptions load whether I use them or not.

04 / When it finds something

Every finding says who fixes it.

Nothing changes unless you ask. Anything that edits a file saves a dated backup first, so you can always go back.

  • We can do itMechanical and undoable — like switching off auto-loading for 14 skills you never use.
  • Claude can helpNeeds a judgement call, so it shows you the edit first. Which rules belong in which folder isn't a script's decision.
  • You, by handIt gives you the command; you run it.
  • Just a habitNothing to install. Knowing is the fix.

The big one — your model — no setting can fix, because you pick it fresh every session. So there's an optional reminder: on your first message it asks whether this job really needs the expensive model, and stays quiet unless it clearly doesn't.

07 / Rolling it out

One of these can go to the whole team.

If you set the budget, the cap was never the fix — giving people the explanation is. That part you can deploy once, centrally, on a Team or Enterprise plan.

  • Hand it outAdd the skill to your organisation's plugin list. People install it once.
  • Run it for themAn admin setting can start it at the beginning of a session. Everyone approves it once, then it stays out of the way.
  • Deploy nothingSimplest version: when someone asks for more budget, ask for their report first. Usually the answer is in it.

Only ever roll out the inspector. It reads settings and counters. The coach reads what people actually wrote — pushed onto a team by their employer, that isn't coaching, it's monitoring. It stays personal and opt-in.

The check counts how much ran on the costly model. It cannot see which of it was hard — so read this as a question worth asking, not a verdict. It used to be called “expensive model on easy work”, which claimed more than it could measure.

Claude Code picks the model once, when the session starts, and keeps it for the whole session. It does not switch to a cheaper one by itself for easy questions. So if your default is the most expensive model, you also pay that rate for 'rename this variable'. Priced at Sonnet's rates instead, the exact same work would have cost $274 a month less. Read that as the most it could save, not a forecast: it assumes Sonnet would have finished every one of those tasks. It is the only figure here that is not plain arithmetic, which is why it is kept out of the headline.

Do this: Switch by hand when you know a session is easy — type /model sonnet — or change your default. Or turn on the optional reminder, which runs once on your first message and stays quiet unless the task clearly does not need what you are paying for:

python3 ".../cost-inspector/scripts/audit.py" --install-hook

Switching model throws away the saved copy of your conversation, so everything said so far gets re-sent at full price once. At your first message that is small change; fifty messages in it is several times worse. Starting on the cheaper model costs nothing at all.

Thinking effort above mediumup to $9.85Claude can help

effort is 'high' (in your user settings)

Effort is how long Claude thinks before it answers. More thinking means more text produced, and you pay for that text. Like the model, it is set once per session and does not adapt per question, so a high default applies to simple jobs too. The good news: dropping effort usually costs you less quality than dropping to a weaker model, so try this lever first. Anything above medium is flagged, including Claude Code's own default — if you have never touched this setting, you are on the expensive end without having chosen it. The figure assumes roughly a third less thinking at medium, so it is an estimate rather than a measurement — which is why it says “up to”.

Do this: Set your default effort to medium, and raise it for the occasional hard task that needs it.

A screenshot goes into the conversation as a picture. One picture costs far more than a line of text, and it stays in the conversation from then on, so you keep paying for it. Memory notes too long$0.99Claude can help

4 of your 11 project memory lists need tidying

MEMORY.md is the contents page for the things Claude remembers about a project, and it loads on every message in that project. It should hold one short line per memory — the details belong in the separate files, which load only when relevant. Two other traps: a memory file missing from the list never gets used at all, and past 200 lines (or 25KB) the rest is dropped and never reaches Claude at all. Only the part that actually loads is charged for — the overflow is a correctness problem, not a cost one.

Do this: Shorten each line to one sentence and move the detail into the file it links to.

Long sessions never clearedup to $152just a habit

25 sessions spent long stretches carrying more than 100k of history — the worst ran 471 messages in a row without a reset

Claude re-sends the whole conversation with every message, so a message near the end of a long chat can cost five times the same message at the start. In a session open all day, a one-line question still carries everything said before it. Anthropic's own cost guidance names this as the biggest single cause of surprise bills.

This is measured on how long a chat stayed big, not how big it got: a session that touched 400k on its final message cost almost nothing extra, while one sitting at 300k for 400 messages paid that every time. Like the model figure, it is an upper bound rather than a forecast — it has to assume all that history was dead weight, and settings alone cannot tell. That is exactly what the companion skill reads conversations to find out, so it is kept out of the headline.

Do this: Type /clear when you switch to unrelated work — it starts fresh and costs nothing. When you do need the history carried forward, /compact is worth it: it re-reads the conversation once, which is one expensive request, but every message after it is far cheaper, so it pays for itself within a few messages. The one time to skip it is when the session is nearly over.

The same kind of action repeated many times5e883b65

Why this pattern costs money: Many small repeated actions cost far more than one batched action, and each result stays in the conversation.

What we saw in your conversation:

You used a single tool call this turn. Prefer browser_batch to execute multiple actions in one call — it is significantly faster.

What it cost you: For about an hour, Claude clicked through the page one action at a time — well over 100 separate steps to build a single small workflow — and each step sent back a screenshot that you then paid for. Claude Code itself suggested grouping the steps after nearly every one of those calls, and the suggestion went unused.

What to do next time: Ask Claude to group the steps: 'do these in one batch, and only stop for a screenshot when you need to see the result before deciding what to do next'.

A long chat kept paying for a part nobody was using5e883b65

Why this pattern costs money: Every message re-sends the whole chat so far, so the longer one runs the more each new message costs. The last message in a long chat can cost five times the first.

What we saw in your conversation:

471 messages in a row, every one of them dragging a short novel's worth of earlier conversation along behind it — the chat was never cleared out or started fresh.

What it cost you: The free report already told you this chat was expensive to carry. What it cannot tell you is when it stopped being worth it — and that is the useful part. The first half of this conversation was one job; once that job was signed off, none of it came up again, but you paid to carry all of it through the 300-odd messages that followed.

What to do next time: That sign-off was the moment to start fresh. When a job is done and the next one is unrelated, type /clear — it costs nothing. When you do still need the history, type /compact: it asks Claude to summarise the old part so you stop paying full price for it, and it earns that cost back within a few messages.
